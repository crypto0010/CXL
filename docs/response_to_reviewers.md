# Response to Reviewers — SplitInfer v2

This document maps every reviewer comment on the rejected manuscript to what
changed. Section numbers refer to `paper/splitinfer_v2.tex`. Where a point is
addressed by code, the path is given; every number cited is regenerated by
`evaluation/make_results_tex.py` from the JSON artifacts.

## Summary of changes

1. **Thesis reframed.** From "a CXL-like coherent memory node at the edge" to
   "when a model exceeds SoC memory, is it cheaper to move memory to compute or
   compute to memory, and where does the answer flip?" Both paths are built over
   one substrate and the crossover is measured by execution (§I, §VI).
2. **New mechanism: `cxlwin`** (§III-A, `splitinfer/cxlwin/`). A host load/store
   window onto FPGA DDR2 with six page states including two transient states,
   explicit host-bias/device-bias ownership, prefetch, and bias-violation
   detection. Positioned honestly as page-granular software DSM (Ivy/Munin/
   TreadMarks), with the CXL Type-2 bias model as an analogy, not an equivalence.
3. **A real evaluation.** The v1 runtime moved no operands (every tensor size
   was recorded as 0), so its 595 ms timed empty round trips. v2 lowers the
   model to INT8, executes it in three modes, and requires bit-exact integer
   agreement between them on every test vector (§IV, §VI, Table II).
4. **Verified data path.** Golden-vector simulation found the v1 RTL could not
   preserve data through DDR2 in either direction and that the MAC array was not
   an 8×8 array. All fixed; four testbenches plus a virtual FPGA that consumes
   the same protocol bytes (`fpga/sim/v2/`, `protocol/src/transport_emul.c`).
5. **Exact DP placer with three placements** replacing a greedy pass that the
   paper had called dynamic programming (`partitioner/solver.py`, verified
   against brute force).
6. **GPU baselines** (TensorRT FP16/INT8) added; CPU baselines kept for
   continuity (§V).
7. **Claims discipline.** Every number is marked measured (M), emulated (E), or
   modelled (C). The board measurement of the v2 data path is pending and is
   said to be pending.

## Reviewer 1

**1. What EdgeCoh guarantees; why CXL.** v1's "coherency" was an ownership
table with no host load/store path — the reviewer was right. v2 adds `cxlwin`:
the host dereferences ordinary pointers into device memory; faults are serviced
by EdgeCoh reads; `release()`/`acquire()` implement the bias flip (§III-A,
Table I, Fig. 3). The paper now states exactly what is and is not guaranteed
("What cxlwin is not", §III-A): page granularity, no snooping, release
consistency between explicit ownership transfers.

**2. One workload end to end; all streaming costs.** E2 runs one program in
every mode on one workload (Table II). Weight staging is reported as
preparation time (334 s at UART for 3.6 MiB) and, for the streaming capacity
case, inside the per-inference latency (E7, Table IV: 32.6 s of a 35.9 s
inference at USB 2.0 is weight streaming). The cost model prices weight
streaming, page faults, dispatch and activation crossings explicitly
(`partitioner/cost_model.py`).

**3. How to interpret the numbers.** The crossover (Fig. 5, Table III) is the
interpretation: NMC over a slow link is not a deployment proposal; it is the
worst-case point of a sweep whose answer is "compute-to-memory pays below ~10^8
B/s and not above." The 1,083× figure is gone with the measurement it came
from.

**4. Baseline choice.** TensorRT FP16 and INT8 GPU baselines added (B3, B4;
`evaluation/baselines/jetson_tensorrt.py`). The reason v1 had none is stated:
the installed onnxruntime has no CUDA provider.

**5. What disaggregation E1/E2 exercise.** Placements are now reported per
layer with candidate costs and crossover bandwidths (manifest v2,
`--report`). The placer's decision for a model that fits host memory is
all-host, and the paper says so (§VI-A). The executed comparison is between
whole-program modes; mixed per-layer execution is listed as future work.

**6. Repeated inference without re-flash.** The controller's DMA-read byte
drop (a plausible cause of the v1 stall) is fixed
(`edgecoh_controller.v`, `dma_rd_have`). The board session document
(`fpga/SYNTHESIS_SESSION_V2.md`) instructs that iterations run without
re-flashing and that any stall is reported as a finding.

**7. The 55× multiplier.** Restated as total weight divided by peak resident
footprint, and corrected: with double-buffered streaming the peak is 2× the
largest layer. E7 executes it (167.6 MiB model, 48 MiB peak) and states its
per-inference price.

**8. Figure 1.** Redrawn in TikZ with four labelled components matching §III.

**9. Writing.** Rewritten. "From ONNX ingestion through DDR2 and back" is now
a concrete verification statement: identical INT32 outputs from host, pool
and NMC executors on every vector.

**10. Repository link.** The repository must be made public before
resubmission (action for the author).

## Reviewer 2

**1. The CXL analogy.** Option (a) taken: a memory-mapped remote-access path
now exists (`cxlwin`). The paper claims the bias model faithfully and the
load/store model only at page granularity, and names software DSM as the
mechanism's ancestor (§II-C, §VIII).

**2. What is new.** Stated as: the controlled comparison between the two ways
of using a memory node, over one link, with one program and bit-exact
outputs; a placer that prices three placements and yields a per-layer
crossover; and the finding that prefetch depth has a sign that depends on the
layer's access sparsity (§VI-B). No novelty is claimed for the DSM mechanism
or for the engines.

**3. The 2.4 h/layer download not reflected.** Now reflected everywhere: in
the cost model, in E7's per-inference latency, and in §VII's conclusion that a
streaming design pays W/B per inference in either placement.

**4. Overlapping text in Fig. 1.** Redrawn.

## Reviewer 3

**1. Why not more SoC memory or local storage.** §VII: above the crossover a
plain memory expander (or SSD) is the right design and NMC's value is bounded
by the slowness of edge links. The paper no longer argues that NMC is
generally preferable; it reports where it is.

**2. What coherence state EdgeCoh maintains.** Table I and Fig. 3. The
consistency problem ownership transfer solves is stated: between `release`
and `acquire` the device's view is authoritative and a host access is a
detected violation; outside it the host's is. Transient states track
outstanding transfers.

**3. Positioning against prior work.** §VIII now covers software DSM (Ivy,
Munin, TreadMarks), weight streaming (FlexGen, DeepSpeed-Inference,
PowerInfer), CXL systems, PIM/NMC, FPGA inference and edge partitioning, with
the specific relation of each.

**4. Partitioning strategy and why dense MACs on a small FPGA.** The placer
is exact and reports per-layer decisions; on a fast link it never chooses the
FPGA for dense MACs, and the paper says the engines are deliberately small
because the question is where compute should sit (§VIII).

**5. TensorRT baseline and a memory-pool configuration.** Both added: B3/B4,
and the pool mode with demand paging, 64/512-page prefetch, and warm variants
(Tables II–III).

**6. Coherence bugs from FSM design.** Agreed. The v2 design uses explicit
transient states in `cxlwin`, a hold-until-accepted MIG handshake, owner-tagged
reads and queued writes in the arbiter, and a byte latch in the controller.
The "lessons" section is now about verification methodology (golden vectors
versus acknowledgement-only tests), not about coherence being hard.
